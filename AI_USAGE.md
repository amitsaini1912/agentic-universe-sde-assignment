# AI Usage Disclosure

## Tools used
Claude (Anthropic), running as an agentic coding assistant with shell access (Claude Code).

## What I used them for
- Most of the implementation was generated by Claude from the assignment README: the
  normalisation functions, SQLite schema, ingest, report derivation, CLI and the test suite.
- Drafting `SUBMISSION.md`.
- Writing a second, independent from-scratch implementation (in-memory, no DB) used only to
  cross-check the five report files on several seeds; it is not part of the submission.

## What I wrote or decided myself
- Chose Assignment A over B.
- Reviewed the design choices recorded in `SUBMISSION.md` (per-file transaction as the idempotency
  unit, linking events to leads at report time instead of at ingest, HMAC + Fernet for PII).

## Where the AI was wrong or unhelpful
- The first version of the ingest tally used a mutable class-level dict to track which files were
  applied (shared state across instances). It was replaced with a simple return value.
- The first draft of the "late-arriving lead" test asserted a loose arithmetic inequality that
  didn't actually prove the behaviour; it was rewritten to check that `batch_003` leads (which only
  arrive in drop 2) appear with calls made before the drop-1 cutoff.
- The AI initially appended lines to the repo's original `.gitignore`; reverted, since the rules say
  keep original files unmodified, and a `solution/.gitignore` was added instead.

## How I verified AI-generated code
- 59 pytest tests covering the rules most likely to break, plus end-to-end idempotency and
  incremental-vs-all-at-once equality.
- Report files diffed against an independent implementation on seeds 42, 7 and 2026 (identical).
- The output reproduces the two values quoted in the spec (`0.5625` connectivity on day 1,
  `2026-10-14T17:55:24+05:30` last call) on seed 42.
- Full DB dump grepped for plaintext names/phones (none); large-scale run timed (~55 s).
